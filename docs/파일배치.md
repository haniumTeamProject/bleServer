# 파일 배치 · 실행 준비

git으로 새로 내려받았을 때 `/monitor`가 바로 뜨도록 하는 데 필요한 파일 배치를 정리한다.

---

## 1. 저장소가 여러 개로 나뉘어 있다

이 프로젝트는 하나의 저장소가 아니다.

| 저장소 | 내용 |
|---|---|
| `backend-python` | FastAPI 서버, `/monitor` 페이지, 위치 판정 로직 |
| `map-tool` | 지도 편집·경로 탐색 도구 (`map_inspection.html`), 평면도·프로젝트 파일 |
| `server/bleapp` | 안드로이드 앱 (팀원 작업분 기반) |
| `server/bledata` | 안드로이드 앱 (초기 작업분) |

`/monitor`는 지도 도구를 같은 페이지로 합쳐서 내려주므로, **서버가 `map-tool`의 파일을 찾을 수 있어야 한다.**

---

## 2. 지도 도구 위치 — 아래 어느 배치든 동작한다

경로를 한 곳에 고정하지 않고 후보를 순서대로 찾는다.

**(A) 형제 폴더로 나란히 (지금 쓰는 배치)**

```
hanieum_project/
  backend-python/
    app/ws/handler.py
  map-tool/
    map_inspection.html
    static/
      map.png
      mappin_project.json
```

**(B) backend-python 안에 넣기**

```
backend-python/
  app/ws/handler.py
  map-tool/
    map_inspection.html
    static/
      map.png
      mappin_project.json
```

(B)는 저장소 하나만 clone해도 되므로 배포·전달이 편하다. 대신 `map-tool`을 별도 저장소로
계속 관리하려면 (A)가 맞다.

**(C) 환경변수로 직접 지정**

```bash
MAP_TOOL_DIR=/원하는/경로/map-tool uvicorn app.main:app
```

찾는 순서는 `MAP_TOOL_DIR` → (B) → (A) → `app/ws/map-tool` 이다. 못 찾으면 `/map`이 404를
돌려주면서 **찾아본 경로를 화면에 표시**하므로, 현장에서 바로 원인을 알 수 있다.

---

## 3. static 폴더 — 평면도와 프로젝트 파일

`/monitor`를 열면 `map-tool/static/` 안의 `.json` 프로젝트 파일을 **자동으로 불러온다.**

```
map-tool/static/
  mappin_project.json   ← 평면도·경로노드·랜드마크·비콘이 모두 들어있음 (약 14MB)
  map.png               ← 원본 평면도 (프로젝트 파일에 이미지가 포함돼 있어 없어도 동작)
```

프로젝트 파일 안에 평면도가 `imageDataUrl`로 들어 있어서, **`.json` 하나만 있으면 지도까지 복원된다.**
`map.png`는 원본 보관용이다.

`/map-static/{파일명}` 으로 서빙하는데, **파일 이름만 받아서** 상위 경로 탈출(`../`)을 막는다.

> 파일이 커서(14MB) git에 올릴 때 주의가 필요하다. GitHub는 100MB 미만이면 받아주지만
> 매번 전체가 다시 올라가므로, 평면도를 자주 바꾸면 저장소가 빠르게 커진다.
> 나중에 백엔드 DB에서 지도를 불러오는 구조로 바뀌면 이 파일들은 저장소에서 빠질 예정이다.

## 4. monitor 페이지가 별도 파일이 됐다

```
backend-python/app/ws/
  handler.py       ← 369행 (웹소켓·라우팅·판정 연결)
  monitor.html     ← 1177행 (화면: HTML + CSS + JS)
  path_tracker.py  ← 400행 (위치 판정)
  rssi_filter.py   ← RSSI 필터 (중앙값 → 칼만 → 히스테리시스)
```

예전에는 `monitor.html`의 내용이 `handler.py` 안의 파이썬 문자열이었다. 1541행 중 1179행(78%)이
문자열이라 에디터가 JS·CSS로 인식하지 못했고, 백슬래시를 두 번 써야 했다.
실제로 CSV 줄바꿈을 `\n` 대신 `\\n`으로 써야 하는 것을 놓쳐 **페이지 전체가 죽는 버그**가 있었다.

**매 요청마다 파일을 읽으므로, 개발 중에는 서버 재시작 없이 `monitor.html`만 고쳐도 반영된다.**

## 5. 실행

```bash
cd backend-python
python -m venv venv && venv\Scripts\activate     # Windows
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

그다음 브라우저에서 `http://localhost:8000/monitor`.

확인 순서:

1. 지도가 자동으로 불러와지는지 (`static/`의 `.json`을 찾음)
2. 상단에 `① 경로 등록 필요` 표시가 뜨는지
3. 앱에서 웹소켓 주소를 넣고 연결하면 비콘 목록이 채워지는지

## 6. 검증 방법

파일 배치를 바꾼 뒤에는 아래를 확인하면 된다.

| 확인할 것 | 방법 |
|---|---|
| 자리표시자 치환 | `/monitor` 응답에 `__MAP_TOOL_CSS__` 같은 문자열이 남아있지 않아야 함 |
| 지도 합병 | 응답에 `class="workspace"` 가 있어야 함 |
| id 중복 | 같은 `id="..."` 가 두 번 나오면 `getElementById`가 한쪽만 잡아 조용히 고장남 |
| HTML 중첩 | 태그 짝이 맞는지 |
| 스크립트 문법 | `<script>` 블록을 뽑아 `node --check` |
| **런타임 오류** | 위 정적 검사로는 못 잡는다. jsdom으로 실제 실행해봐야 함 |

마지막 항목이 중요하다. TDZ 오류(변수 선언 전 접근)처럼 **문법은 통과하는데 실행하면 스크립트가
통째로 죽는** 종류의 버그가 실제로 있었고, jsdom 실행 테스트로만 잡혔다.
