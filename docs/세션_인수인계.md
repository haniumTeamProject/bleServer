# 인수인계 — 새 세션에서 이어서 작업하기

이 파일 하나로 맥락이 넘어가도록 쓴다. 새 컴퓨터·새 대화에서 **이것부터 읽으면 된다.**

정리 시점: 2026-08-22

## 0. 대화 기록은 못 옮긴다

이 작업은 **Cowork**(Claude 데스크톱 앱)에서 했다. Claude Code(터미널 CLI)가 아니다.

대화 기록은 앱 안쪽에 있고, **디스크에서 찾아 복사할 수 있는 경로를 확인하지 못했다.**
에이전트 쪽에서는 `%APPDATA%\Claude\local-agent-mode-sessions\...` 로 보이는데
PowerShell 에서 `Test-Path` 하면 `False` 다 — 샌드박스 안의 경로다.

실재하는 것은 이 둘뿐이다.

```
%APPDATA%\Code\agent-host\        SDK·claude.exe — 엔진. 앱 깔면 생긴다
C:\Users\User\.claude\projects\   Claude Code(CLI) 세션. 이 작업과 무관
```

**그래서 이 문서가 대화 기록을 대신한다.** 아래 §7 에 "왜 그렇게 정했나"와
"무엇이 안 되나"를 전부 적었다. 더 깊은 내용은 §6 의 문서들에 있다.

## 1. 무엇을 만들고 있나

한이음 2026 6팀. **시각장애인 실내 음성 길안내.**

BLE 비콘을 복도에 깔고, 스마트폰이 잡은 RSSI 로 서버가 위치를 판정해서
"왼쪽으로 꺾으세요"를 읽어준다. 사용자는 화면을 볼 수 없다 — 이 전제가
설계 판단 대부분의 근거다. 잘못 안내해도 **사용자가 알아챌 방법이 없다.**

```
bleServer        FastAPI. 위치 판정 · 경로 · 안내 문구 · 관리자 API      ← 주 작업
APP-FE           안드로이드 사용자앱. 스캔하고 읽어주기만 한다
WEB-FE           관리자웹(React). 설계도·마스크·비콘·경로노드 편집
default_server   옛 자바 백엔드
map-tool         실측 좌표 편집 도구
firmware         ESP32 비콘
```

### 역할 분담이 핵심이다

```
서버가 정한다    무엇을 말할지, 언제 들을지, 지금 어디인지
앱은 실행한다    말하고, 마이크 열고, 진동하고, 스캔 결과를 올린다
```

앱에 판단을 두면 **조용히 틀린다.** 예전에 후보가 여럿일 때 말없이 첫 번째를
고르던 코드가 그랬다. 그리고 문구 하나 고칠 때마다 빌드·배포·업데이트를
기다려야 해서 실측 한 번에 하루가 갔다.

그래서 서버가 앱에 보내는 메시지는 **모양이 하나**다.

```
utterance     읽을 문장. null 이면 아무 말도 안 한다
listenAfter   true 면 발화가 끝난 뒤 마이크를 연다
haptic        진동 패턴
state         ready | listening | navigating | arrived
screen        title / items / step / totalSteps
```

앱은 `event` 로 분기하지 않아도 동작한다.

## 3. 작업 규약

새 세션에서 이어갈 때 **지켜야 하는 것들.**

```
WEB-FE 는 되도록 건드리지 않는다. 고칠 곳이 있으면 먼저 말하고 승인받는다
APP-FE 를 크게 바꿀 때도 먼저 말한다
커밋 메시지는 바꾼 것만 쓴다. 이유는 md 에만 남긴다
답은 짧게
펌웨어는 이미 구워져 있다고 전제한다. major/minor 를 1,1 로 가정하지 않는다
마음대로 고치지 않는다. 요청하지 않은 필터·보정을 끼워 넣지 않는다
```

md 파일은 "무엇을 했나"가 아니라 **"왜 그렇게 했나"와 "무엇이 안 되나"**를 남기는
곳이다. 실패했던 시도와 그 이유를 지우지 않는다.

### 도구 관련 주의

- **APP-FE / WEB-FE 에서 에이전트가 `git` 을 실행하면 안 된다.** `index.lock` 이
  남아서 사용자 쪽 git 이 막힌다. 실제로 두 번 그랬다. 읽기만 할 때는
  `git --git-dir=<repo>/.git log` 처럼 워킹트리를 안 건드리는 형태로 쓴다
- 상태를 보려면 `git archive HEAD | tar -x -C /tmp/...` 로 꺼내서
  `diff -rq --strip-trailing-cr` 로 비교한다. 인덱스를 안 건드린다

## 5. 구조 — 알고 있어야 판단이 되는 것들

### 5.1 두 갈래로 나뉜 것

```
무엇을 말할지    경로 노드가 정한다     app/nav/cues.py
언제 말할지      비콘이 정한다          app/ws/path_tracker.py
```

**섞으면 안 된다.** 노드는 지도의 기하이고 비콘은 폰이 감지할 수 있는 유일한
신호인데, 성질이 달라서 한 덩어리로 다루면 어느 쪽 문제인지 구분이 안 된다.

### 5.2 웹소켓이 둘이다

```
/ws              붙어 있는 전부에게 뿌린다.  전역 필터·추적기 하나.  /monitor 용
/ws/navigation   그 연결에만 보낸다.        연결마다 필터·추적기.   사용자앱
```

**상태를 하나도 공유하지 않는다.** 앱을 `/ws/navigation` 으로 옮겼더니 `/monitor`
가 통째로 비었고, `app/ws/monitor_mirror.py` 로 **한 방향만** 중계해서 해결했다.
반대 방향은 없다 — 모니터에서 누른 것이 폰의 안내를 건드리면 안 된다.

키 모양도 다르다.

```
/ws              "MAC|이름"      옛 앱이 JSON 키로 올리던 것
/ws/navigation   "major-minor"   아직 안 잡힌 비콘도 경로에 세우려고
```

`/monitor` 는 `|` 뒤쪽을 비콘 이름으로 보므로, 중계할 때 DB 이름을 붙여
`"101-1|ESP32-B1"` 로 만들어 보낸다.

### 5.3 추적 키가 `major-minor` 인 이유

RSSI 스트림 키(`"MAC|이름"`)는 **폰이 그 비콘을 한 번이라도 잡아야** 생긴다.
그래서 목적지를 말하는 순간 경로에 넣을 수 있는 건 "지금 잡히는 것"뿐이었고
20칸짜리 경로가 2칸으로 줄었다. `major/minor` 는 DB 가 알고 펌웨어에 새겨져
있어서 **폰이 아직 못 봤어도 미리 세워둘 수 있다.**

`major = 100 + 층`, `minor = 그 층의 번호`. major 를 같이 넣는 이유는 minor 가
층 안에서만 유일하기 때문이다.

### 5.4 경로 노드

노드는 **코너·맞은편·입구에만** 있다. 긴 복도는 양 끝 두 점뿐이라 그 사이 비콘이
통째로 빠진다. 그래프에 노드를 더 넣으면 관리자웹과 갈라지므로, 노드는 그대로
두고 **경로 계산 때 선을 1m 간격으로 훑는다**(`route_engine._walk`). 그 표본은
저장되지 않는다.

```
corner      경계가 꺾이는 곳. concave=true 면 벽 끝
landmark    목적지 출입구 (계단·엘리베이터도 여기 포함)
facing      위 둘의 맞은편 벽. pairKind 로 누구 맞은편인지

wall   벽 짚고 걷는 구간
cross  손 떼고 건너는 구간 — **단방향**, a(입구/벽끝) → b(맞은편)
```

건너기에 걸리는 규칙이 **둘**이다. 둘 다 `pathfind.ts` 에 있고 서버도 둘 다 지켜야 한다.

```
① 목적지 건너기 제한   목적지(landmark)에서 뻗는 건너기는 그 목적지가 출발지일 때만
② 단방향              a(입구·벽 끝) → b(맞은편) 으로만
```

②는 맞은편 지점이 허공이라 거기서 출발할 수 없어서고, ①은 지나가는 길에 남의 방 문
앞을 지름길로 가로지르면 그 목적지에 있지도 않은 사람에게 "손을 떼세요"가 나가서다.
포팅할 때 ②를 `False` 로 뭉갰던 적이 있고, ①은 아예 빠져 있었다(2026-08-23 수정).

층 하나 = `floor_path_nodes` 행 하나. 종류별로 안 쪼갠다. 좌표는 마스크 픽셀
기준이라 `mask_w` 를 같이 저장하고 읽을 때 900(설계도) 좌표로 환산한다.

거리는 저장하지 않는다 — 축척을 고치면 저장된 그래프를 안 건드려도 따라 바뀌게.

### 5.5 안내 배정 — "소유 방식"

사용자가 정한 방식이다. **노드에서 가장 가까운 경로 비콘이 주인**이고, 안내는
그 주인의 **한 칸 앞** 비콘에서 나간다. 코너에 있는 비콘에서 "꺾으세요"라고 하면
이미 코너를 지난 뒤다.

두 가지를 조심해야 한다.

- **반경으로 자르지 않는다.** 한때 3m 안에서만 주인을 찾았더니 2.9m 는 살고
  3.2m 는 안내가 통째로 사라졌다
- **순서를 건너뛰지 않는다.** 같은 비콘이 두 번 나오는 경로에서는 좌표만으로
  어느 쪽 칸인지 못 가린다. 주인 index 가 앞으로만 가게 막았다. 중복이 없으면
  이 제약을 안 건다

도착만은 예외로 **마지막 비콘에 고정**한다. 한 칸 앞을 적용했더니 평균 6m,
최악 15m 전에 "계단1입니다"가 나갔다.

### 5.6 진행 판정

`PathTracker`. 모드 셋(`trend`/`segment`/`confirm`), 기본은 `confirm`
(= segment + 무장 500ms + 5dB 재확인).

```
FORWARD_STREAK = 2    패킷 수. 시간이 아니다 (32~118 evaluate/s → 17~62ms)
BACK_STREAK    = 3
```

**후퇴 판정에 `next_rising` 가드가 있다.** 코너를 돌 때 현재 비콘은 이미 떨어졌는데
다음이 아직 안 올라온 골짜기에서 "경로를 벗어났습니다"가 나가던 문제 때문이다.
다음 비콘이 오르는 중이면 되돌아가는 게 아니라 골짜기를 지나는 중으로 본다.

`_audible_idx()` 가 **안 들리는 칸을 건너뛴다.** 경로에는 아직 한 번도 안 잡힌
비콘도 들어 있어서, 바로 옆 칸만 보면 거기서 판정이 멈춘다.

### 5.7 층을 넘는 안내

`app/nav/legs.py`. 목적지 층이 다르면 `[가까운 연결자, 최종 목적지]` 로 쪼개고
**한 층짜리 안내를 두 번 돌린다.**

층 그래프를 합치지 않은 이유는 거리가 뜻을 잃어서다 — "조금 뒤"를 가르는 기준은
바닥을 걷는 거리인데 계단이 섞이면 거짓말이 된다. 그리고 층을 옮기는 동안
신호가 실제로 끊겨서 한 경로로 이어두면 그 구간이 경로 이탈로 읽힌다.

**`arrived` 는 최종 목적지에서 한 번만 나간다.** 추적기는 경유지에 닿아도 똑같이
`isLast` 를 올리므로, 세션의 `legs`/`leg_index` 만이 둘을 가릴 수 있다.
그 상태를 두는 목적이 `arrived` 를 내보내기 위해서가 아니라 **내보내지 않기
위해서**다. 앱은 이 구조를 모른다.

## 7. 밟았던 지뢰

같은 데 두 번 빠지지 않으려고 적는다.

| 무엇 | 어떻게 드러났나 |
| --- | --- |
| **ESP32 가 UUID 를 바이트 역순으로 광고한다** | UUID 필터를 넣었더니 비콘이 **전부** 걸렸다. 펌웨어가 `setManufacturerId(0x4C00)` 을 쓰는 것과 같은 이유. 양쪽 순서를 다 받게 고쳤다 |
| **칼만 필터는 신호가 끊겨도 값을 안 잃는다** | 층을 옮긴 뒤 떠나온 층 비콘이 여전히 제일 세서 출발점으로 뽑혔다. `strongest_beacon_key(filters, major)` 로 층을 거른다. **지우지는 않는다** — 판정이 흔들렸다 돌아오면 못 되돌린다 |
| **`session.major` 가 출발 층에서 None 이었다** | 첫 층만 MAC 으로 정하고 그 뒤로만 major 로 따라가서. 위의 필터가 첫 층에서 아예 안 걸리고 있었다. 지금은 층이 그대로여도 major 를 저장한다 |
| **LLM 에 UUID 를 넘기면서 few-shot 은 `A1` 이었다** | "411호로 가죠" → 410호. 목적지를 `L1..Ln` 으로 정규화해 넘기고 결과를 되돌려 푼다 |
| **에이전트 git 이 `index.lock` 을 남긴다** | APP-FE·WEB-FE 에서 두 번. 사용자 git 이 막혔고 에이전트는 그 파일을 못 지운다 |
| **Konva 는 `devicePixelRatio` 를 캔버스 생성 때 한 번만 읽는다** | 브라우저 확대하면 화질이 깨졌다 |
| **flex 자식은 `min-width: auto`** | 내용보다 작아지지 못해 지도가 안 줄어들었다. `min-w-0` 이 답이었는데 나는 엉뚱한 데를 두 번 짚었다 |
| **MSW 핸들러가 `VITE_API_BASE_URL` 을 따라간다** | `.env` 만 바꿔도 mock 이 계속 붙었다 |
| **`_walk()` 의 `int()` 절삭** | 1~2m 구간이 끝점 하나로만 표본화된다. 그 사이에서만 이길 수 있는 비콘이 빠진다 |
| **`speak()` 는 항상 QUEUE_FLUSH** | `ArrivalFragment` 가 자기 문장을 말하면서 서버 문장("407입니다")을 잘라먹었다 |
| **`bleServer` 의 main 과 공통 조상이 없다** | 그냥 PR 을 열면 병합이 거부된다 |
| **경로 탐색이 관리자웹과 갈라져 있었다** | `find_node_path()` 에 목적지 건너기 제한(①)이 없어서 757쌍 중 205쌍이 다른 경로였다. 픽스처가 `directed`·노드 `type` 을 안 실어 테스트가 못 잡았다 |
| **CRLF 오경보** | 78개 파일이 CRLF 로 오염됐다고 내가 잘못 말했다. 내 리눅스 샌드박스에 `core.autocrlf` 가 없어서였다. 사용자 쪽 `$noise.Count` 는 0이었다 |

## 9. 실측 도구

`/monitor` (`app/ws/monitor.html`). 브라우저에서 연다.

- RSSI 그래프(원본 + 칼만), 판정 근거 숫자, 막힌 조건 이름
- 판정 설정(임계값·모드·확인 대기)을 화면에서 바꾸면 **폰 안내에도 반영된다**
- 목적지를 보내면 세 방식(거리·소유·절충) 비교 표와 지도 우측 패널이 채워진다
- 안내가 시작되면 CSV·그래프가 **자동 저장**된다.
  이름은 `출발_목적지_시각` — 폴더를 이름순 정렬하면 같은 구간끼리 모인다

```
bleServer/measurements/B26_407_20260822-100712.csv    tests/eval_tracker.py 형식 그대로
bleServer/measurements/B26_407_20260822-100712.json   경로·판정설정·전환시점
```

CSV 를 기존 형식에 맞춘 이유는 **다시 돌려볼 수 있어야** 해서다.

```
python tests/eval_tracker.py --sweep-full
```
