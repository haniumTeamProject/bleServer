# 개발 환경 준비

서버를 처음 띄우거나, 받아온 뒤 안 돌 때 보는 문서.

---

## ⚠ DB 재구축이 필요하다 (통합 작업 중)

**결론부터: 통합이 끝나기 전에 한 번은 DB를 지우고 다시 만들어야 한다.**

이유는 서버가 테이블을 이렇게 만들기 때문이다.

```python
# app/main.py
@app.on_event("startup")
def on_startup():
    Base.metadata.create_all(bind=engine)
```

`create_all` 은 **없는 테이블만 만든다.** 이미 있는 테이블의 컬럼이 바뀌어도
아무것도 하지 않는다(Java 의 `ddl-auto=update` 와 비슷하지만 그보다 약하다).
마이그레이션 도구(Alembic 등)를 안 쓰고 있으므로, 컬럼이 늘면 **직접 지우고
다시 만드는 수밖에 없다.**

### 스키마 변경 — **적용됨. 재구축해야 한다**

WEB-FE 접합 작업으로 아래가 바뀌었다. 근거는 `docs/WEBFE_접합_변경기록.md`.

| 테이블 | 변경 |
|---|---|
| `beacons` | `connector_id` 제거, `is_anchor` 제거, `source_uid`·`source_label` 추가 |
| `landmarks` | `type` → `category`(자유 입력), `source_uid`·`source_label` 추가 |
| `floors` | `status` 제거(계산값으로), `scale_m_per_px` 추가 |
| `buildings` | `status` 제거(계산값으로), `created_at` 추가 |
| `connector_positions` | **신설** — 연결자가 각 층 어디에 있는지 |

**이미 DB 를 만들어 뒀다면 지금 상태로는 서버가 제대로 안 돈다.**
`create_all` 이 기존 테이블의 컬럼 변경을 반영하지 않기 때문이다.

### 아직 안 한 스키마 변경

| 테이블 | 추가할 컬럼 | 왜 필요한가 |
|---|---|---|
| `landmarks` | `door_side` | 도착 안내 「문은 오른쪽에 있습니다」 (템플릿 13·14번) |
| `buildings` | UUID | 비콘 UUID 로 건물 자동 판별. 결정 대기 |

**경로노드 테이블은 만들지 않는다.** 노드(코너·벽 끝·건너기 도착점)는 전부
이동영역 마스크에서 기하학적으로 계산되는 값이고, 관리자가 손으로 넣는 값이 없다.
마스크가 이미 DB 에 있으므로 필요할 때 다시 만들면 된다.
안내에 쓰이는 관리자 입력값(`doorSide`, 난간·버튼 방향)은 랜드마크와 연결자에 붙는다.

### 재구축 절차 — Windows 에 설치한 PostgreSQL 기준

이 프로젝트는 **Windows 설치본 PostgreSQL** 을 쓴다(서버는 WSL 에서 돌리고
DB 는 Windows 쪽에 있다). Docker 가 아니다.

**데이터를 다 지우므로, 지우면 안 되는 게 있는지 먼저 확인할 것.**
지금 단계에서 DB 에 든 것은 관리자 계정과 시험용 건물·층 정도다.

#### 0. 서버부터 끈다

uvicorn 이 떠 있으면 연결을 잡고 있어 작업이 막힌다. 터미널에서 `Ctrl+C`.
pgAdmin 을 열어뒀다면 그것도 닫는다.

#### 1. SQL Shell (psql) 로 접속

시작 메뉴에서 **SQL Shell (psql)** 을 연다. 접속 정보를 차례로 묻는다 —
**여기에 psql 명령을 치는 게 아니라 값만 답한다.**

```
Server [localhost]:        ← 엔터 (기본값)
Database [postgres]: wayfinder
Port [5432]:               ← 엔터
Username [postgres]: wayfinder
wayfinder 사용자의 암호: wayfinder
```

비밀번호는 `.env` 의 `DATABASE_URL` 에 있다
(`postgresql+psycopg2://wayfinder:wayfinder@localhost:5432/wayfinder`).

`wayfinder=>` 프롬프트가 뜨면 접속된 것이다.

#### 2. 테이블을 지운다

```sql
DROP TABLE IF EXISTS
  admins, beacons, buildings, connector_positions, connectors,
  floor_masks, floorplans, floors, landmarks
CASCADE;
```

`\dt` 로 확인. "어떤 테이블도 없습니다" 가 나오면 비워진 것이다.

> **`DROP DATABASE` 나 `DROP SCHEMA` 는 쓰지 않는다.**
> `wayfinder` 계정이 DB·스키마의 소유주가 아니라서
> `must be owner of ...` 로 막힌다. 테이블은 `create_all` 이 이 계정으로
> 만들었으므로 소유주가 맞아 지울 수 있다. 결과는 같다.

목록에 없는 테이블이 남아 있으면 전부 훑어서 지운다.

```sql
DO $$ DECLARE r RECORD; BEGIN
  FOR r IN SELECT tablename FROM pg_tables WHERE schemaname = 'public'
  LOOP EXECUTE 'DROP TABLE IF EXISTS public.' || quote_ident(r.tablename) || ' CASCADE'; END LOOP;
END $$;
```

#### 3. 서버를 켠다

```bash
cd backend-python
uvicorn app.main:app --reload --port 8000
```

`create_all` 이 테이블을 새로 만든다. psql 에서 `\dt` 로 9개가 보이면 된다.

```
admins  beacons  buildings  connector_positions  connectors
floor_masks  floorplans  floors  landmarks
```

**`connector_positions` 가 있으면** 최신 스키마가 반영된 것이다.
컬럼도 확인할 수 있다.

```sql
\d beacons     -- source_uid·source_label 있고, connector_id·is_anchor 없어야 함
\d floors      -- scale_m_per_px 있고, status 없어야 함
```

#### 4. super_admin 계정을 다시 만든다

DB 를 비웠으므로 계정도 사라졌다. 회원가입으로 만들어지는 계정은 전부
`role: admin` 이고 `super_admin` 을 만드는 API 가 없다.

```sql
-- 관리자웹에서 회원가입을 한 번 한 뒤에 실행
UPDATE admins SET role = 'super_admin', status = 'active' WHERE email = '<내 이메일>';
```

#### 참고 — 명령줄에서 한 번에

SQL Shell 대신 터미널에서 바로 실행할 수도 있다. 설치 버전에 맞게 경로를 고친다
(`16`, `17`, `18` 등).

```bash
# WSL 에서
"/mnt/c/Program Files/PostgreSQL/18/bin/psql.exe" -U wayfinder -d wayfinder \
  -c "DROP TABLE IF EXISTS admins, beacons, buildings, connector_positions, connectors, floor_masks, floorplans, floors, landmarks CASCADE;"
```

```bash
cd backend-python
```

### `--host 0.0.0.0` 은 대부분 필요 없다

`--host` 는 **어느 네트워크 인터페이스로 들어오는 연결을 받을지** 정한다.

| | 뜻 |
|---|---|
| 기본값 `127.0.0.1` | 루프백만. 같은 기계에서만 접속 가능 |
| `0.0.0.0` | 가진 주소 전부. 같은 공유기의 다른 기기도 접속 가능 |

기본값이 루프백인 건 안전 때문이다. 개발 서버가 실수로 밖에 노출되면 곤란하다.

**지금 구성에서는 붙일 이유가 없다.**

- 관리자웹은 같은 PC에서 `localhost:5173` → `localhost:8000` 이다.
- 사용자앱은 cloudflare 터널로 붙는다(`BleScanner.java:80`). `cloudflared` 가
  같은 기계에서 로컬 포트에 붙으므로 루프백으로 충분하다.

**WSL 이면 `0.0.0.0` 을 줘도 폰에서 바로 안 붙는다.** WSL2 는 NAT 뒤에 있어서
Windows 쪽에 `netsh interface portproxy` 를 따로 걸어야 한다. 터널을 쓰는 이유가
이것이다.

같은 공유기의 폰에서 **직접**(터널 없이) 붙일 때만 `--host 0.0.0.0` 을 붙인다.

### Postgres 가 없으면 **서버가 아예 안 뜬다**

`create_all` 이 startup 에서 도는데, DB 연결이 안 되면 거기서 죽는다.

```
sqlalchemy.exc.OperationalError: connection to server at "localhost", port 5432 failed
ERROR:    Application startup failed. Exiting.
```

이 경우 WebSocket 도 REST 도 전부 안 붙는다. `check_pipeline.py` 가
「WebSocket 연결 ✗」로 나오면 **먼저 서버 터미널을 볼 것.** 원인이 코드가 아니라
DB 인 경우가 많다.

Windows 설치본은 서비스로 돌아간다. 꺼져 있으면 켠다.

```powershell
# PowerShell (관리자)
Get-Service postgresql*          # 상태 확인
Start-Service postgresql-x64-16  # 버전 번호는 설치본에 맞게
```

```bash
# WSL 에서 붙는지만 확인
pg_isready -h localhost -p 5432   # 없으면: nc -z localhost 5432
```

기본 접속 정보는 `app/config.py` 의 `database_url` 이다.

```
postgresql+psycopg2://wayfinder:wayfinder@localhost:5432/wayfinder
```

### websockets 버전

점검 스크립트가 `websockets` 를 쓴다. 버전에 따라 API 가 다르다.

```
websockets 12  → await connect(...) 결과가 async 컨텍스트 매니저가 아님
websockets 14  → 지원함
```

`tests/check_pipeline.py` 는 **양쪽에서 다 돌도록** 짜여 있다(try/finally + close).
12.0 과 14.1 에서 통과를 확인했다. 새 스크립트를 쓸 때 `async with await
websockets.connect(...)` 형태를 쓰면 구버전에서 깨진다.

## 지도 데이터

경로 탐색은 map-tool 이 내보낸 프로젝트 파일을 읽는다.

```
map-tool/static/mappin_project.json
```

### 경로 그래프가 들어 있어야 한다

이 파일에 `pathNodes` / `pathEdges` 가 없으면 경로를 못 찾는다.
지도 편집 도구에서 **「프로젝트 저장」** 을 눌러 받은 파일이어야 한다.

| 버튼 | 나오는 파일 | 경로 그래프 |
|---|---|---|
| **프로젝트 저장** | `mappin_project.json` | **있음** ← 이걸 쓴다 |
| 검수 완료 · 저장 | (모달에 표시) | 다른 형식(`path_nodes`) |
| .json 파일 다운로드 | `corridor_polygons.json` | 검수 데이터를 내려받는 것 |

확인:

```bash
python3 -c "import json;d=json.load(open('../map-tool/static/mappin_project.json',encoding='utf-8'));print('노드',len(d.get('pathNodes') or []),'엣지',len(d.get('pathEdges') or []))"
```

0 이 나오면 경로 노드가 생성되지 않은 상태로 저장한 것이다. 도구에서
「경로 노드 생성」이 끝난 뒤(화면에 노드 점이 보인다) 다시 저장할 것.

파일 위치를 바꾸려면 `MAP_TOOL_DIR` 환경변수를 쓴다.

## 점검 순서

문제가 생기면 위에서부터 차례로.

```bash
# 1) DB 가 떠 있나 (Windows 서비스)
pg_isready -h localhost -p 5432

# 2) 서버가 떴나 (터미널 로그 확인)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/docs

# 3) 음성 목적지 전 구간
python tests/check_pipeline.py
python tests/check_pipeline.py --load      # 걸으면서 말하는 상황 재현

# 4) 로직 회귀 (서버 없이 도는 것들)
python tests/test_landmark_matcher.py      # 규칙 엔진
python tests/test_llm_matcher.py           # LLM 방어 장치
python tests/test_route_engine.py          # 경로 탐색
python tests/eval_tracker.py               # 위치 판정 (실측 13개)

# 5) 관리자웹 접합 (Postgres 없이 돈다 — SQLite 메모리)
python tests/test_webfe_contract.py        # 경로·필드가 WEB-FE 와 맞는지
python tests/test_admin_api.py             # 실제 왕복
```

`eval_tracker` 는 ③ 모드가 **26/31 매칭, 정지오탐 0** 이면 정상이다.
