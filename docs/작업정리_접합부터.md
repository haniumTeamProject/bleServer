# 관리자웹 접합 ~ 현재까지 — 작업 정리

관리자웹(WEB-FE)과 붙이기 시작한 시점부터 지금까지 백엔드에 들어간 것 전부.
왜 그렇게 했는지는 `WEBFE_접합_변경기록.md` 에 자세히 적혀 있고, 이 문서는
**무엇이 들어갔고 무엇이 남았는지**를 한눈에 보기 위한 것이다.

---

## 1. 무엇을 만들었나

### 관리자웹과의 계약

34개 엔드포인트를 전수 대조했다. WEB-FE 의 mock 핸들러(`src/mocks/handlers.ts`)를
**계약의 정본**으로 삼았다 — 화면들이 그 mock 을 상대로 개발되어 실제로 동작하므로
거기 적힌 경로·필드가 곧 명세다. 문서보다 코드가 정확했던 사례가 실제로 있었다
(명세서는 `/api/accounts`, 구현은 `/api/admin/accounts`).

| 고친 것 | 전 → 후 |
|---|---|
| 계정 승인 경로 | `PATCH /accounts/{id}/status` → `PATCH /accounts/{id}` |
| 랜드마크 분류 | `type` 고정 4종 → `category` 자유 입력 |
| 비콘 타입 | `anchor\|checkpoint\|connector` → `semantic\|reinforcement` |
| 연결자 위치 | `Beacon.connector_id` → `ConnectorPosition` 테이블 |

새로 만든 엔드포인트 6개: `GET/PATCH /api/admin/me`, `GET/PUT /api/floors/{id}/scale`,
`PUT/DELETE /api/buildings/{bid}/connectors/{cid}/positions/{floorId}`.

### 조용히 틀리고 있던 것 둘

**`sourceUid` 가 버려지고 있었다.** map-tool 재가져오기의 매칭 키인데 저장되지
않아서, 다시 가져올 때마다 비콘이 전부 새로 생성되고 관리자가 입력한 MAC 이
옛 항목에만 남았다. pydantic 기본값이 `extra="ignore"` 라 422 도 안 났다.

**층 상태가 되돌아가지 못했다.** `floors.status` 에 저장하고 단계마다 한 칸씩
올리기만 해서, 설계도를 지워도 `ready` 로 남았다. 관리자가 화면에서 "안내 가능"을
보는데 실제로는 안내가 안 되는 상태가 만들어졌다. 조회할 때마다 계산하도록 바꿨다
(`app/status.py`).

### 안내 엔진

| 모듈 | 하는 일 |
|---|---|
| `app/nav/map_source.py` | 지도 데이터 공급자 추상화 (파일 / DB) |
| `app/nav/db_map_source.py` | DB 구현 — 마스크·비콘·목적지·그래프 |
| `app/nav/path_nodes.py` | **관리자웹의 노드 생성기를 그대로 옮긴 것** |
| `app/nav/route_engine.py` | 다익스트라 + 비콘 순서 + 회전 방향 |
| `app/ws/navigation.py` | 목적지 → 경로 → 추적기 |
| `app/ws/llm_matcher.py` | 말한 문장을 목적지에 잇는다 (규칙 엔진 폴백) |

**노드 생성기 이식이 이 구간의 핵심이다.** 관리자가 화면에서 확인한 경로와
사용자가 안내받는 경로가 다르면 검수가 의미를 잃는다. 기대값을 손으로 적지 않고
**원본 TS 를 실제로 실행해서** 뽑아 대조했다.

```bash
node --experimental-strip-types tests/fixtures/gen_pathnodes_reference.mjs
python tests/test_path_nodes.py
```

실측 4층(2372×1790, 입구 24개)에서 노드 102개·연결 150개가 **좌표 오차 0.000e+00**
으로 일치한다.

### 끊겨 있던 사슬을 이었다

```
STT 텍스트 → 목적지 매칭 → 경로 생성 → 비콘 순서 → 추적 판정
```

`route_engine` 은 만들어져 있었는데 `handler.py` 가 import 조차 하지 않아서,
목적지를 알아들어도 경로를 만들지 않았다. 경로는 `/monitor` 에서 사람이 비콘
순서를 손으로 등록해야 돌았다.

```
"사백칠호" → 407 → 48m / 69초 / 비콘 8개 → 추적기 등록
```

### `/monitor` 를 다시 만들었다

지도 편집 도구(map-tool) 3,200줄을 이 페이지에 통째로 합쳐 넣고 있었다.
그 도구는 자기 알고리즘으로 노드를 만들었는데 관리자웹이 만든 것과 눈에 띄게 달랐다.
이제 서버가 관리자웹 그래프를 정확히 재현하므로 그것을 받아 그린다 —
**화면에 뜨는 것과 안내에 쓰는 것이 같은 값**이라 갈라질 수가 없다.

지운 것: `/map`, `/map-static`, `_extract_map_tool_parts()`.

목적지는 드롭다운이 아니라 **입력창에 친 문장이 폰 음성과 똑같은 메시지로** 나간다.
목록에서 고르면 정작 확인해야 할 구간(말이 목적지에 붙는가)을 건너뛴다.

## 2. 검증

```bash
python tests/test_path_nodes.py           # 원본 TS 출력과 대조        21개
python tests/test_route_from_db.py        # DB → 마스크 → 노드 → 경로   14개
python tests/test_destination_to_route.py # 말 한마디 → 추적 등록       14개
python tests/test_map_db.py               # /map-db 피드              34개
python tests/test_webfe_contract.py       # 프론트 계약 대조            9개
python tests/test_admin_api.py            # 관리자 API 왕복            30개
python tests/test_route_engine.py         # 경로 엔진                 24개
python tests/test_landmark_matcher.py     # 목적지 매칭               66개
python tests/test_llm_matcher.py          # LLM 매칭                 13개
```

`test_webfe_contract.py` 는 WEB-FE 의 mock 과 도메인 타입을 직접 읽어 비교한다.
**프론트가 바뀌면 이 테스트가 먼저 깨진다.**

`test_path_nodes.py` 의 기대값은 원본 TS 실행 결과다. 관리자웹이 알고리즘을 고치면
생성 스크립트를 다시 돌려 **따라가야 할 변경이 무엇인지** 그 자리에서 드러나게 했다.

## 3. DB 재구축이 필요하다

`Base.metadata.create_all()` 은 없는 테이블만 만든다. 컬럼 변경은 반영되지 않는다.
절차는 `개발환경_준비.md` 참고.

| 테이블 | 변경 |
|---|---|
| `beacons` | `connector_id`·`is_anchor` 제거, `source_uid`·`source_label` 추가 |
| `landmarks` | `type` → `category`, `source_uid`·`source_label` 추가 |
| `floors` | `status` 제거, `scale_m_per_px` 추가 |
| `buildings` | `status` 제거, `created_at` 추가 |
| `connector_positions` | 신설 |

## 4. 최근 발견 — 고친 것

### 4-1. 층을 안 가리고 모든 목적지에서 골랐다

4층에서 "화장실"이라고 말하면 **1층 화장실이나 다른 건물 화장실**이 후보로 올라왔다.
`_load_landmarks_from_db()` 가 등록된 전 층을 한 통에 담았기 때문이다.

이름이 겹치는 것이 정상인 값들이라(화장실·계단·엘리베이터는 층마다 있다) 되묻기가
무의미해지고, 운 나쁘면 갈 수 없는 곳으로 안내한다.

**층을 모르면 빈 목록을 준다.** 아무 층이나 골라 답하는 것보다 "모르겠다"가 낫다 —
잘못 안내하면 사용자가 알아챌 방법이 없다.

- 폰: 지금 잡히는 비콘이 어느 층에 등록됐는지로 정한다
- `/monitor`: 고른 층(`floorId`)을 같이 보낸다

### 4-2. 층을 지워도 딸린 것이 남았다

`delete_floor` 가 `floors` 행 하나만 지웠다. 이 스키마에는 외래키 제약이 없어서
(`floor_id` 가 전부 그냥 String) DB 가 대신 정리해 주지 않는다. 비콘·랜드마크·
설계도·마스크·연결자 좌표가 **주인 없는 행으로 남았다.**

쌓이기만 하는 게 아니다. 목적지 목록처럼 층을 거치지 않고 테이블을 직접 훑는 곳에서는
지운 층의 데이터가 그대로 나온다.

### 4-3. 폰이 안 붙어 있으면 경로를 통째로 버렸다

경로를 만드는 것(지도만 있으면 됨)과 추적을 거는 것(폰이 비콘을 올려야 함)을
한 덩어리로 봤다. 그래서 이미 계산해 둔 경로가 있는데도 `routeError` 로 처리해
지도로 확인하는 것조차 막혔다.

이제 `route` 는 언제나 내려가고, 추적 여부는 `tracking`·`trackingNote` 로 따로
알린다. `routeError` 는 **경로 자체를 못 만들 때만** 나온다.

## 5. 남은 것

### 5-1. 경로 노드를 DB 에 저장해야 한다 — **결정 번복**

`WEBFE_접합_변경기록.md` §6 에서 "테이블을 만들지 않기로 했다"고 적었다.
근거는 "노드는 마스크에서 계산되는 값이고 관리자가 손으로 넣는 값이 없다"였다.

**그 전제가 틀렸다.** 관리자웹 경로노드 화면에 노드를 옮기는 기능이 있다.

```typescript
// WEB-FE/src/pages/pathnodes/PathNodePage.tsx
function onNodeMove(id, x, y) { ... }     // 노드를 끌어서 옮긴다
// 되돌리기/다시실행(Ctrl+Z/Y)도 있다
```

**손으로 옮긴 것은 마스크에서 다시 계산할 수 없다.** 지금은 그 수정이
`localStorage` 에만 남아서, 브라우저를 바꾸면 사라지고 **서버는 아예 모른다.**
관리자가 옮겨놓은 노드로 검수했는데 안내는 원래 자리로 나간다.

계산값과 수정값을 구분해서 저장해야 한다.

| 방식 | 담는 것 |
|---|---|
| 전체 저장 | 노드·연결을 통째로. 단순하지만 마스크를 고치면 손수정이 묻힌다 |
| **수정분만 저장** | 옮긴 노드의 id·좌표만. 마스크에서 다시 만든 뒤 그 위에 덮는다 |

수정분만 저장하는 쪽이 낫다 — 마스크를 고쳐도 손수정이 살아남는다.
다만 id 가 `N01`, `N02`… 순번이라 **마스크가 바뀌면 같은 id 가 다른 자리를 가리킨다.**
좌표 기준으로 다시 붙이는 규칙이 필요하다.

### 5-2. 폰이 major/minor 를 안 보낸다

지금은 MAC·광고 이름만 올린다. 그래서 서버가 층을 알아내려고 이름으로 DB 를 뒤진다.
`major`(=100+층)를 실어 보내면 그 조회가 사라진다.

두 군데를 손봐야 한다.

- **펌웨어**: 지금 전 비콘이 `setMajor(1); setMinor(1)` 이다. 비콘별로 다시 구워야 한다
- **앱**: `BleScanner` 가 제조사 데이터(0x004C)를 파싱해서 major/minor 를 뽑아 올려야 한다

과도기에는 MAC·이름으로도 매칭되게 해뒀다(`map_source.resolve_beacon`).

### 5-3. 그 밖에

| 항목 | 상태 |
|---|---|
| map-tool 이 `uid` 를 안 만든다 | `sourceUid` 가 항상 비어 재가져오기가 중복 생성 |
| `toDesignCoords` 가 `workW` 대신 `origW` | 평면도가 3200px 넘으면 좌표가 밀린다 |
| 관리자웹이 백엔드에 안 붙어 있다 | MSW 가 `/api/*` 를 가로챈다 (`WEBFE_백엔드_연결_수정안.md`) |
| 첫 관리자를 만들 수단이 없다 | 시드 스크립트로 때우는 중 |
| 벽 마스크가 휘발성 | 관리자웹도 저장하지 않는다 |
| 경로노드 튜닝값(12m·5m)이 DB 에 없다 | 화면에서 바꿔도 서버는 기본값을 쓴다 |
| 층간 이동 안내 | 미구현 |
