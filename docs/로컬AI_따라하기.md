# 로컬 AI 목적지 매칭 — 따라하기

말로 한 목적지("변소 급해요")를 실제 랜드마크("화장실 1")에 이어주는 부분을
로컬 LLM으로 돌리는 절차. 순서대로 따라가면 된다.

**막히면 언제든 이걸 돌려라.** 어느 단계에서 걸렸는지와 해결법을 알려준다.

```bash
python tests/check_llm.py
```

---

## 0. 이게 왜 필요한가 (1분)

규칙만으로 되는 것과 안 되는 것이 갈린다.

```
규칙으로 됨    "407호로 가줘" → 407      "사백칠" → 407      "409" → 409(1)/409(2)
규칙으로 안 됨  "변소" → ?               "승강기" → ?        "커피 마실 데" → ?
```

동의어와 자연스러운 문장은 사전을 아무리 늘려도 끝이 없다. 게다가 사전은 건물마다
달라서 코드에 박아두면 다른 건물에서 오히려 방해가 된다.
그래서 그 부분만 LLM에 맡긴다.

**안 깔아도 서버는 돌아간다.** 규칙 엔진으로 자동으로 넘어가서 방 번호와
종류+순번("두 번째 화장실")은 그대로 동작한다. 동의어만 못 알아듣는다.

---

## 1. 어디에 깔아야 하나 ← 제일 자주 틀림

**FastAPI 서버가 도는 그 컴퓨터.** 폰도 아니고 개발용 노트북도 아니다.

```
[안드로이드 폰]  ──웹소켓──▶  [FastAPI 서버]  ──HTTP──▶  [Ollama]
                              └────────── 같은 기계 ─────────┘
```

`llm_matcher.py` 가 `http://localhost:11434` 로 부르기 때문이다.
서버가 `hanium.mcsmtp.org` 에 있으면 **거기에** 깔아야 한다.

다른 기계에 두려면 7장 참고. 다만 안내 응답이 빨라야 해서 같은 기계가 낫다.

---

## 2. 설치

### Windows
[ollama.com/download](https://ollama.com/download) 에서 받아 실행. 설치하면 백그라운드에서 자동으로 뜬다.

### Linux (서버가 리눅스면 이쪽)
```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
sudo systemctl status ollama          # 떠 있는지 확인
```

### macOS
```bash
brew install ollama && brew services start ollama
```

**확인**

```bash
python tests/check_llm.py
```
2단계까지 `✓` 가 나오면 성공. `연결 실패` 가 나오면 서버가 안 뜬 것이다.

---

## 3. 모델 받기

```bash
ollama pull exaone3.5:7.8b
```

LG AI연구원의 **EXAONE 3.5** — 한국어·영어 이중 언어 모델이라 한국어 표현을 잘 잡는다.
(EXAONE 4.0은 아직 Ollama 공식 지원이 없다.)

받는 데 몇 분 걸린다. 서버 사양에 맞춰 고르면 된다.

| 모델 | 내려받기 | 필요 메모리 | 어떤 경우에 |
|---|---|---|---|
| `exaone3.5:2.4b` | 1.6GB | 4GB↑ | 작은 VPS·라즈베리파이 |
| `exaone3.5:7.8b` | 4.8GB | 8GB↑ | **기본값** |
| `exaone3.5:32b` | 19GB | 32GB↑ | GPU가 있을 때 |

작은 모델로 바꾸려면 환경변수만 고친다.

```bash
export LLM_MODEL=exaone3.5:2.4b
```

**확인** — `python tests/check_llm.py` 에서 3단계 `✓`

---

## 4. 모델이 대답하는지

```bash
ollama run exaone3.5:7.8b "안녕하세요"
```

대답이 나오면 된다. 처음에는 모델을 디스크에서 올리느라 수십 초 걸릴 수 있다.

**확인** — `python tests/check_llm.py` 에서 4단계. 응답 시간도 같이 보여준다.

```
4단계. 모델 응답 (첫 호출은 적재 시간이 얹힙니다)
  ✓ 응답 0.43초
     원문: {"ids": ["L11"], "why": "방 번호 407"}
```

> 첫 호출이 타임아웃(6초)에 걸리면 정상이다. 모델 적재 때문이다.
> FastAPI 서버는 **뜰 때 자동으로 예열**하므로 실제 운영에서는 문제가 없다.
> 수동으로 깨우려면 위 `ollama run` 을 한 번 돌리면 된다.

---

## 5. 목적지 해석이 되는지

`python tests/check_llm.py` 5단계가 이렇게 나오면 끝이다.

```
  ✓ '407호로 가줘'    → resolved   407                (0.31초)  방 번호
  ✓ '사백칠'          → resolved   407                (0.28초)  한글 수사
  ✓ '변소 급해요'      → ambiguous  ['화장실 1','화장실 2'] (0.52초)  동의어
  ✓ '승강기 어딨어요'   → ambiguous  ['엘리베이터 1','엘리베이터 2']  동의어
  ✓ '409'           → ambiguous  ['409(1)','409(2)'] (0.30초)  되묻기
  ✓ '옥상정원'        → notFound   -                  (0.35초)  거절
```

**"변소"와 "승강기"가 잡히면 LLM이 실제로 일하고 있는 것이다.**
이 둘은 규칙 엔진으로는 절대 안 된다.

---

## 6. 서버에 붙이기

따로 할 일이 없다. FastAPI를 띄우면 자동으로 붙는다.

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

뜰 때 로그를 보면 된다.

```
[목적지] LLM 준비 완료: exaone3.5:7.8b (23.4초)      ← 정상
[목적지] LLM 예열 실패(...): Connection refused      ← Ollama가 안 떠 있음
```

**폰에서 확인** — 앱의 `🎤 목적지 말하기` 를 누르고 "변소"라고 말한다.

```
🎤 "변소"
🔊 "화장실 1번, 화장실 2번 중에서 말씀해 주세요."
🎤 "두 번째"          ← 안내가 끝나면 마이크가 자동으로 켜진다
🔊 "화장실로 안내합니다."
```

## 7. 다른 기계에 둘 때

Ollama는 기본적으로 `127.0.0.1` 에만 열려 있다.

**Ollama 쪽** (리눅스)
```bash
sudo systemctl edit ollama
```
```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
```
```bash
sudo systemctl restart ollama
```

**FastAPI 쪽**
```bash
export LLM_BASE_URL=http://192.168.0.10:11434
export LLM_TIMEOUT=10        # 네트워크 왕복이 더해지므로 늘린다
```

> **인증이 없다.** 공인 IP에 그대로 열지 말고 사설망이나 방화벽으로 막아둘 것.

## 8. 문제 해결

| 증상 | 어느 단계 | 해결 |
|---|---|---|
| `연결 실패 Connection refused` | 2 | Ollama가 안 떠 있다. `systemctl start ollama` 또는 `ollama serve` |
| `'exaone3.5:7.8b' 이 없습니다` | 3 | `ollama pull exaone3.5:7.8b` |
| 첫 응답만 느리거나 실패 | 4 | 모델 적재 시간. 서버가 자동 예열하므로 운영에선 무해 |
| 응답이 3초 넘게 걸림 | 4 | 모델이 크거나 CPU만 쓰는 중. `exaone3.5:2.4b` 로 낮춰볼 것 |
| **방 번호는 되는데 "변소"만 안 됨** | — | **LLM이 안 붙어 규칙 엔진으로 도는 중.** 서버 로그에서 예열 성공 확인 |
| `LLM이 목록에 없는 id를 냄` 로그 | — | 정상. 지어낸 답을 걸러낸 것이라 사용자에겐 안 나간다 |
| 메모리 부족으로 서버가 느려짐 | — | 더 작은 모델로 바꾸거나 `LLM_PROVIDER=off` |

가장 헷갈리는 건 **다섯 번째 줄**이다. LLM이 안 붙어도 서버는 조용히 규칙 엔진으로
돌아가기 때문에, 증상이 "일부만 안 됨"으로 보인다. 그럴 땐 로그부터 확인하라.

## 9. 환경변수 전체

| 변수 | 기본값 | 설명 |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` / `openai` / `off` |
| `LLM_MODEL` | `exaone3.5:7.8b` | 모델 태그 |
| `LLM_BASE_URL` | `http://localhost:11434` | Ollama 주소 |
| `LLM_TIMEOUT` | `6` | 평소 응답 대기(초) |
| `LLM_WARMUP_TIMEOUT` | `120` | 예열 대기(초) |
| `LLM_KEEP_ALIVE` | `30m` | 모델 유지 시간. `-1` 이면 안 내림 |
| `LLM_VERIFY_NUMBER` | `1` | 방 번호 검증. `0` 이면 끔 |

LLM을 아예 끄려면:
```bash
export LLM_PROVIDER=off
```

## 10. 알아둘 것 — 왜 이렇게 만들었나

### 출력을 목록 안으로 제약한다
LLM이 자유 텍스트를 내면 없는 장소를 지어낸다. 그래서 랜드마크 id 목록을 주고
그중에서만 고르게 하고, 돌아온 id가 목록에 없으면 버린다.
프롬프트로 부탁하는 게 아니라 **구조로** 막는다.

### 번호를 검증한다
사용자가 "407"이라고 분명히 말했는데 LLM이 406을 고르면 시각장애인이 잘못된 문
앞에 서게 된다. 발화에 방 번호가 뚜렷하면 결과와 대조해서 다르면 버린다.

### 없어도 돌아간다
모델 죽음 / JSON 파싱 실패 / 전부 환각 / 번호 불일치 → 전부 규칙 엔진으로 넘어간다.
연속 실패하면 30초간 호출을 건너뛰어서 매번 타임아웃을 기다리지 않는다.

### 캐시
목적지 종류가 몇십 개뿐이라 금방 대부분이 캐시에 들어가고, 그때부터 지연이 사라진다.
같은 말 3번 → 모델 호출 1번.

### 되묻기는 LLM을 안 부른다
"두 번째" 같은 순서 표현은 규칙으로 100% 정확하고, 후보가 이미 좁혀진 상태라
LLM이 보탤 게 없다. 괜히 부르면 지연만 생긴다.
